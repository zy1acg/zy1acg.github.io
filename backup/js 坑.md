## 类型转换

> [!warning] 
> 在 JavaScript 中，`console.log(Number({}));` 的结果是 `NaN`，这是因为 **JavaScript 引擎在将对象转换为数字时，经历了一个失败的类型转换过程**。

具体来说，当调用 `Number()` 并传入一个对象时，引擎会按照 ECMAScript 规范执行以下步骤：

### 1. 第一步：对象转换为原始类型
`Number()` 函数无法直接处理对象，它需要先将对象转换为一个**原始值**（如字符串、数字等）。

将对象转换为原始值时，JavaScript 会依次调用对象上的两个方法：
1.  首先调用 `valueOf()` 方法。
2.  如果 `valueOf()` 返回的仍然不是原始值（比如返回了对象本身），则继续调用 `toString()` 方法。

对于普通的空对象 `{}`：
*   **调用 `({}).valueOf()`**：默认情况下，普通对象的 `valueOf()` 会返回对象自身，也就是 `{}`。因为它不是原始值，转换继续。
*   **调用 `({}).toString()`**：普通对象的 `toString()` 方法会返回一个表示该对象的字符串。对于普通对象，这个字符串固定是 **`"[object Object]"`**。

所以，对象 `{}` 被转换成了字符串 `"[object Object]"`。

此时，相当于执行了：
👉 `Number("[object Object]")`

### 2. 第二步：字符串转换为数字
现在，`Number()` 函数接收到了字符串 `"[object Object]"`，它需要尝试将这个字符串解析为数字。

根据字符串转数字的规则：
*   如果字符串是一个合法的数字格式（如 `"123"`、`"3.14"`），则转换为对应的数字。
*   如果字符串是纯空格（如 `"   "`），则转换为 `0`。
*   **如果字符串包含任何非数字字符（且不是纯空格），则无法解析，结果为 `NaN`（Not a Number）。**

显然，字符串 `"[object Object]"` 包含了字母和方括号，根本不是一个合法的数字格式。

因此，解析失败，最终结果为 **`NaN`。

---

### 转换链路总结：
`Number({})`
➡️ 调用 `({}).valueOf()`  // 返回 `{}`，不是原始值
➡️ 调用 `({}).toString()` // 返回 `"[object Object]"`
➡️ `Number("[object Object]")` // 尝试解析这个字符串为数字
➡️ `NaN` // 包含非数字字符，解析失败

### 扩展理解：数组为什么不一样？
作为对比，我们看看为什么 `Number([])` 的结果是 `0`，而 `Number([1, 2])` 是 `NaN`：

*   **`Number([])`**：
    *   `[].valueOf()` 返回数组本身 `[]`，不是原始值。
    *   `[].toString()` 返回空字符串 `""`（因为数组为空）。
    *   `Number("")` 解析空字符串，结果是 `0`。

*   **`Number([1, 2])`**：
    *   `[1, 2].valueOf()` 返回数组本身，不是原始值。
    *   `[1, 2].toString()` 返回 `"1,2"`。
    *   `Number("1,2")` 包含逗号，不是合法数字，结果是 `NaN`。

### 进阶：如何让 `Number({})` 不返回 NaN？
如果你在自己定义的对象中重写了 `valueOf()` 或 `toString()` 方法，返回一个可以合法转换为数字的原始值，那么结果就会改变：

```javascript
let obj = {
    valueOf() {
        return 42; // 返回一个原始值（数字）
    }
};
console.log(Number(obj)); // 42

let obj2 = {
    toString() {
        return "100"; // 返回一个可以解析为数字的字符串
    }
};
console.log(Number(obj2)); // 100
```

对于普通对象 `{}` 来说，由于它默认的 `toString()` 返回的 `"[object Object]"` 无法被解析为数字，所以 `Number({})` 的结果必然是 `NaN`。
