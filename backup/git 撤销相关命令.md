## git 撤销相关命令

Git 里好几个命令都能撤销，你是不是一直分不清？用错一个，后果能差出十万八千里，今天真机挨个演示。

- 先看 git revert 这个最安全的：提交历史是 v1、v2、v3 三次提交，revert 最新这次，内容确实退回 v2，但看提交记录，v3 还在，只是多加了一条反向提交——历史完整保留，安全用在已经推送的公共分支上。

- 再看 git reset --hard 这个最危险的：同样退回到之前，内容也是 v2，可提交记录呢，v3 直接从历史里消失了——不是多一条记录，是把指针硬拽回去，提交被抹掉。如果这些提交已经推送过，别人那边还是旧历史，一同步就冲突。

- 最后是 git restore 这个最轻量的：改乱了文件但还没提交，restore 一下，直接恢复成上次提交的样子——这个过程根本不涉及任何提交历史，最安全。

> [!tip]
> 一句话记住怎么选：还没提交的改乱了用 restore，已经推送共享的提交用 revert，只有本地自己的提交才能用 reset --hard。
